# 《豬豬夢工場：30 天豬生逆襲》後續開發藍圖

> **文件版本：** 1.0\
> **規劃基線：** 2026-11-17 已公開版本\
> **定位：** 以小步推出、保持 30 天養成節奏、保護既有存檔與每日挑戰公平性為原則。\
> **估時說明：** 下列 S／M／L 為單人開發的粗略工作量級，不是承諾日期；包含設計、實作與測試，不含大型美術製作。

## 1. 方向摘要

遊戲目前已有 30 天養成、七種豬豬個性、三種夢想專精、NPC 好感任務、宿敵元元與四場牧場競賽、隱藏成就、世代傳承、排行榜、PWA 離線遊玩等系統。後續不宜只堆疊數值或一次性事件；最有價值的方向，是讓遊戲**記得玩家做過的選擇**，並讓一輪結束後仍有值得追求的目標。

建議優先順序：

1. **事件連鎖接入遊戲**：完成已有劇本的執行器，是內容量與重玩價值提升最大的工作。
2. **元元賽後友情線**：延續已建立的宿敵角色，讓四場比賽有賽後回響。
3. **牧場建設**：為豬豬幣增加長線用途，提供可控、溫和的養成選擇。
4. **既有故事角色的 NPC 支線**：把事件鏈角色延伸成可再次相遇的角色，而非一次增加許多新關係數值。
5. **世代挑戰／新遊戲＋目標**：擴充現有傳承，形成跨局目標，同時避免永久加成膨脹。

## 2. 目前版本基線

### 已上線內容

- GitHub Pages 遊戲網站及 Cloudflare Worker + D1 線上排行榜。
- 30 天行動養成、天氣、心情、突發事件、小遊戲、結局圖鑑與每日挑戰。
- 七種豬豬個性、學者／騎士／明星夢想專精、專屬事件與夢想尾聲。
- 母牛老師、松露攤老闆好感任務；元元的四場競賽、宿敵故事與分支對話。
- 「黃緞帶的約定」隱藏成就及通關尾聲；永久成就與世代傳承。

### 已設計、尚待接入的內容

事件連鎖已有 JSON 劇本、Schema、劇本文件及模擬工具；目前規格列出六條線、36 個節點、67 個選項與 19 個鏈結局，但事件鏈執行器尚未接進主要遊戲事件流程。這是 Roadmap 的第一優先，應先完成資料與執行流程整合，再新增更多一次性事件。

## 3. Roadmap 總覽

| 階段 | 優先級 | 主要交付 | 粗估工作量 | 依賴 |
| --- | --- | --- | --- | --- |
| 0. 上線穩定與回饋 | P0 | 確認正式版、存檔／PWA／排行榜的健康狀態 | S，2–4 個工作日 | 無 |

| 2. 元元賽後友情線 | P1 | 競賽後的關係收束與多種尾聲 | M，1–2 週 | 現有競賽與敬意狀態 |

若以單人、每階段完成後測試與小幅調整為前提，全部規劃約需 **7–12 週**；建議依玩家回饋調整，不必一次做完才發布。各階段都應可獨立合併、獨立上線。

## 4. 各階段詳細規劃

### 階段 0｜上線穩定與回饋（P0，S）

**目標：** 確認目前公開版本在玩家常見裝置上穩定，再開始增加狀態與事件複雜度。

**工作範圍：**
- 以手機與桌面瀏覽器各走完一輪：開局、行動、事件、競賽、結局、成就與重新開局。
- 確認 GitHub Pages 新版提示、PWA 快取與離線重開正常。
- 確認一般排行榜、每日挑戰排行榜能讀取；上傳失敗時不阻斷養成。
- 收集玩家回報的問題與困惑點；先使用自願回報或 issue，不新增未告知玩家的追蹤分析。
- 建立一份「已知問題／平衡待觀察」清單，作為後續驗收基線。

**完成條件：**
- 正式網站可開啟，核心遊玩不依賴 API Key 或網路。
- PWA 更新後能載入新版；舊版快取不會造成白畫面。
- 排行榜不可用時遊戲仍可完整通關，錯誤提示清楚。

### 階段 1｜事件連鎖引擎與劇情上線（P0，L）

**目標：** 讓角色能記得玩家的選擇，讓一輪 30 天不再只是互不相干的單點事件。

**建議拆成三個可發布里程碑：**

#### 1A. 最小執行器與存檔相容

- 載入 `data/events.js` 作為遊戲可離線讀取的劇本資料；保留 JSON 為編輯正本。
- 新增 `chains` 狀態：進行中章節、已完成鏈、選擇旗標及有限長度歷史。
- 舊存檔從 v1 遷移至新版本；舊玩家可續玩，未完成的普通養成資料不重置。
- 事件日優先順序：先續接進行中的事件鏈，再依候選分數抽新鏈，沒有合適鏈時走原本事件池。
- 沿用既有事件彈窗；顯示章節標題、鎖定選項原因、選擇後結果、稱號／日記獎勵。
- 每日挑戰完全不啟用事件鏈，固定種子、事件順序與全球公平性不變。
- 關閉分頁或重新整理後，能續接同一章，不重複發獎或重複套用選項效果。

#### 1B. 分批開放五條主線

建議先以兩條驗證系統，再擴充剩餘三條：

1. **迷路的小雞**：作為教學線，讓玩家體驗「選擇會被記住」。
2. **松露攤的秘密**：測試金幣、商店及好感度的複合效果。
3. **圖書館的禁書**：延伸母牛老師與牧場世界觀。
4. **牧場保衛戰**：以力量與同理心共同解決事件。
5. **星空舞台**：讓魅力與夢想選擇影響支線收束。

每條鏈只在一般養成的既有事件日出現，不額外消耗行動日；同一時間最多一條鏈進行中，其他符合條件的故事留待之後事件日。

#### 1C. 隱藏線與整體潤飾

- **傳說豬的試煉**：前五條主線完成至少三條後，在第 21–29 天區間解鎖。
- 隱藏線不在未解鎖前直接透露名稱或條件；完成後給予稱號及敘事收束，不提供過強數值獎勵。
- 上線前完整執行劇本結構驗證、Schema 驗證及大量可玩性模擬。

**完成條件：**
- 每條鏈都能從起點走到至少一個結局；所有分支結局在模擬中至少走到一次。
- 有門檻的選項都有清楚的鎖定說明；每個劇情旗標都由玩家可理解的選擇設定。
- 測試證明：每日挑戰不受影響、舊存檔可載入、重新整理可續章且不重複發獎。
- 手機上章節文字與選項不溢出；每個事件最多四個可見按鈕。
- 新增劇本資產後，Service Worker 快取版本同步更新。

**主要風險與對策：** 事件連鎖若搶走太多事件日會讓玩家錯過一般事件。以「事件鏈只共用事件日」、每次至多一條進行中、機率與優先權可調整來控制密度；初版不新增額外天數成本。

### 階段 2｜元元賽後友情線（P1，M）

**目標：** 讓元元的故事在第四場競賽後繼續，而不是比賽結束就消失。

**建議內容：**
- 以既有競賽戰績、尊敬度及「黃緞帶的約定」成就狀態作為劇情分支資料，不再建立第二套重複的好感數值。
- 在第 28 天競賽後或結局頁提供一段賽後對話；結局頁可選擇「約定下次再比」、「一起籌備元元盃」等互動。
- 依勝／平／負與參賽完整度呈現不同台詞，但每條路線都能得到情感收束，避免只有全勝才有正向內容。
- 全平手隱藏尾聲仍保留為獨立彩蛋；其他戰績的賽後內容不得覆蓋該尾聲。
- 可新增「元元盃籌備」或「晨露牧場來信」一項可收集日記／紀念物，先不加入永久戰鬥性數值。

**完成條件：**
- 四場後至少有三種可辨識的賽後回應（例如高敬意、普通交情、未完整參賽）。
- 隱藏成就仍只由既有條件解鎖；原有主要結局判定不改變。
- 舊存檔沒有競賽欄位或競賽未完成時可安全顯示預設敘事。

### 階段 3｜牧場建設 MVP（P1，M）

**目標：** 為金幣提供新的策略用途，讓玩家在「現在花掉」與「為長線升級存錢」之間做決策。

**第一版範圍：**
- 只做三種設施：**閱讀角**（智慧路線）、**泥巴訓練場**（力量路線）、**小小舞台**（魅力路線）。
- 每種設施先做兩級升級；提供一個外觀變化與小幅、有限次數的單局加成。
- 以現有商店／關係面板入口管理，不新增每日行動種類，避免 30 天玩法太複雜。
- 升級只影響一般養成；每日挑戰不採用建設加成，維持固定條件。
- 第一版使用單局投資，先觀察金幣曲線；永久牧場擴建暫緩，避免跨代數值膨脹。

**平衡原則：**
- 設施提供的總收益不得高於約 1–2 次有效行動價值。
- 不得讓某項設施成為所有路線的必買選擇；避免永久加成與成就、傳承重複疊加。
- 玩家金幣不足時依然能正常養成；不可將必要劇情或主要結局鎖在付費／高額建設之後。

**完成條件：**
- 三項設施在單局內均可被選擇；升級、存檔續玩及通關重開不會重複消費或丟失狀態。
- 經模擬確認不同個性／專精不會因建設而失去平衡。
- 每日挑戰測試確認沒有引用一般養成的設施狀態。

### 階段 4｜NPC 故事延伸（P2，M）

**目標：** 增加可記住玩家選擇的配角，而不是單純把好感度條越做越多。

**建議做法：**
- 優先從事件鏈已出現的角色延伸：迷路小雞、小狼／狼群夥伴、舞台夥伴等，避免同時引入大量新人物。
- 先推出一條 2–3 章短支線；條件由既有事件鏈結局或明確好感門檻觸發。
- 儘量沿用事件旗標與支線結局紀錄；只有當角色互動需要跨多章量化關係時才新增獨立好感值。
- 故事獎勵以日記、稱號、角色卡、有限數值為主；避免每條線都增加永久能力。

**完成條件：**
- 新支線至少有兩種由玩家選擇造成的後續差異，並有清楚結尾。
- 不會與母牛老師／松露攤老闆任務同日搶事件而令任務無法完成。
- 重玩同一條線時結果可預期，玩家能從日誌或角色回話看出自己的選擇留下了痕跡。

### 階段 5｜世代挑戰與新遊戲＋（P2，M）

**目標：** 延伸既有退休與祖傳特質，創造跨多局的目標，但保留每一代仍需自行養成的挑戰。

**建議內容：**
- 新增「家族紀錄」頁，記錄每代結局、傳承特質、元元競賽獎盃與支線稱號。
- 每代通關後提供一張家族目標卡，例如「三代各完成不同夢想」、「家族累積兩座競賽獎盃」或「完成三條不同事件鏈結局」。
- 完成目標以收藏徽章、家族日記與外觀為主；如提供永久能力，需設上限並避免與既有成就無限疊加。
- 保留玩家選擇是否退休傳承；新手與只玩一局的玩家不應被強迫進入 NG+。
- 將家族紀錄加入存檔匯出／匯入格式，與現有隱私原則一致：不包含 API Key、暱稱或裝置識別碼。

**完成條件：**
- 跨局目標在重新載入、匯出及匯入後仍一致；舊存檔缺少家族紀錄時可自動補預設值。
- 新遊戲＋獎勵不會讓每日挑戰獲得優勢；每日挑戰仍固定使用中立狀態。
- 每項目標文字清楚說明進度，不能只靠玩家看不見的隱藏旗標判定。

## 5. 跨階段品質門檻

每個階段在發布前都必須通過以下檢查：

1. **存檔相容：** 新增狀態有明確版本遷移；舊存檔、匯入存檔及損毀欄位都有安全預設值。
2. **公平性：** 每日挑戰的固定種子、天氣、事件序列與中立成長倍率不被一般模式新系統污染。
3. **離線性：** 新資料加入 Service Worker 資產清單；無 API Key、無網路時核心遊戲仍可玩。
4. **可測試性：** 所有隨機結果可在測試中固定；新支線每個分支都有可重現測試。
5. **手機可用性：** 事件文字短、按鈕可點、彈窗不超出視窗；至少測試窄螢幕及鍵盤／觸控互動。
6. **部署安全：** 遊戲前端更新不需要更動 production D1；排行榜 schema 若有變更，先在 Preview 驗證並確認 migration 為向前相容。
7. **玩家透明：** 劇情條件、獎勵與鎖定理由在需要時可於遊戲內找到；隱藏成就只隱藏驚喜，不製造不公平的永久損失。

## 6. 建議的發版節奏

- **版本 A：** 事件鏈引擎 + 小雞／松露兩條線，作為垂直切片，確認存檔、離線、UI 與優先序。
- **版本 B：** 加入禁書、保衛戰、星空舞台；發布後觀察事件密度與單局完成率。
- **版本 C：** 解鎖傳說豬隱藏線，並推出元元賽後友情線。
- **版本 D：** 上線牧場建設 MVP；優先平衡金幣與行動價值。
- **版本 E：** 增加 NPC 短支線及家族目標卡，依玩家回饋決定是否擴大 NG+。

每次發版先更新測試與 PWA 快取版本，再合併至 `main`；Cloudflare D1 僅在確有 schema 變更時執行 migration。所有階段盡量使用短 PR，讓測試失敗或平衡問題能快速回退。

## 7. 明確暫緩項目

- 即時多人競賽、聊天、玩家對戰或需要持續伺服器狀態的玩法。
- 全面重寫為大型前端框架；除非單檔結構已明確阻礙功能，否則維持低建置成本。
- 未經玩家同意的跨站追蹤或行為分析。
- 付費抽卡、限時付費能力或會造成公平性疑慮的 monetization。
- 為每個新角色各自新增永久屬性與多條好感條，造成介面和數值負擔。

## 8. 成功指標（先以非侵入方式觀察）

- 玩家是否能在一輪 30 天內至少完成一條事件連鎖，並理解故事如何受選擇影響。
- 事件鏈是否有多條可達結局，且一般單點事件仍有出場空間。
- 元元賽後故事是否讓不同戰績的玩家都得到完整收束。
- 牧場建設是否讓金幣選擇更有意義，而不是形成固定必買答案。
- 舊玩家續玩、新玩家開局、離線遊玩與每日挑戰公平性是否維持正常。

初期建議用自願問卷、GitHub Discussions／Issues 及玩家回報檢視這些指標，不預設新增遙測。若未來真的需要匿名統計，應先公開用途、資料欄位、保留期限與退出方式。

---

**總結：** 先把已寫好的事件連鎖接進現有遊戲，再延伸元元與牧場的關係；等敘事循環成熟後，才加入建設經濟與跨世代目標。這樣能先提升「每一輪故事都不同」的感受，同時把數值膨脹和每日挑戰風險控制在可管理範圍。
